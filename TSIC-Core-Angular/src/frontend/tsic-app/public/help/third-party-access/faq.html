3rd Party Data Access

Grants apply immediately — no confirmation step.

Clicking Grant access or Re-Activate is the decision. If you click the wrong row, Inactivate it — that also takes effect immediately.

Exactly what data does the third party get?

Two things, per event: rosters — player and parent names and email addresses — but only for age groups you have flagged Third-Party Roster Access in the L-A-D-T Editor, and the event's full schedule. If no age groups are flagged, an active login still gets the schedule but no roster data.

The third party I want isn't in the picker. How do I add them?

You can't from this screen — it's reuse-only. The picker lists only logins that have already been authorized for your organization at least once. A first-time authorization is set up with your TSIC administrator; once it exists, it appears here and you manage it across events yourself.

How do I switch an event from one provider to another?

Inactivate the current provider on that event first, then grant the other. Each event allows only one active third party at a time — the console will refuse a grant while another login is still active on the event.

Does Inactivate delete anything?

No. It immediately stops the third party from signing in to that event, but the authorization history is kept — the row shows Inactive and a one-click Re-Activate. Data the third party already downloaded is not recalled by inactivating.

What does "Access window ends" mean?

The date the third-party login expires on that event. After it passes, the login can no longer sign in even if it is still marked Active. Only events with an open access window appear in this table.

An active grant only ever releases some age groups' rosters. Why?

Roster release is opt-in per age group: in the L-A-D-T Editor, each age group has a Third-Party Roster Access flag. Only flagged age groups are included in the download — a common setup releases graduating-year age groups to a recruiting service while keeping younger ones private.

Who can use this screen?

Organization-level administrators only. Per-event directors don't see it — granting an outside agency access to player data is an organization-level decision, and it covers every event the organization runs.

Tip: when an event's recruiting period ends, come back and Inactivate the login rather than letting the access window run out — the "N active" badge at the top of the screen makes it easy to spot events still releasing data.
