Widget Editor

Widgets are the panels and tiles that make up a Dashboard. This screen is where you decide which widgets exist, which kinds of events get them automatically, and which individual events get something different.

A widget needs two things to appear.

A developer has to build it, and you have to set it up here. Building it alone does nothing — it stays invisible until it has a definition on this screen and is assigned to an event.

The three tabs

  • Widget Definitions — the catalog of every widget that exists, with its name, category, and where it's currently deployed. Add, edit, and delete widgets here.
  • Job Overrides — what one specific event gets. Add a widget to just this event, or switch off one it would otherwise inherit.
  • Default Matrix — the automatic rules. Anything ticked here is given to every event of that type, for the roles you choose.

Reading the "In Use" column

The Definitions tab tells you where each widget has actually landed:

  • 3 jobs — attached to three specific events. Click it to open Job Overrides.
  • auto · 7 — an automatic rule gives it to seven job types, no per-event setup needed.
  • Not in use — defined, but nobody sees it. Usually means it's built and waiting.

Turning a widget on for one event

  1. Open Job Overrides. It opens on the event you're currently in.
  2. Expand the workspace and find the widget's row.
  3. Tick the box under each role that should see it.
  4. Save Overrides.

Turning it back off

Use the at the end of the widget's row, then save. The button tells you which it will do:

  • Remove from this job — you added it here, so it goes away cleanly.
  • Revert to inherited — an automatic rule supplies it, so the row returns to that rule.

The row button only appears when the row actually differs from what the event would inherit.

Role Assignments in the widget dialog reach every event.

The Role Assignments section inside Add/Edit Widget writes automatic rules — it applies to every event of the job types you tick, not the one you're looking at. To change a single event, use Job Overrides.

Colours in the override matrix

  • Inherited — comes from an automatic rule; you haven't touched it.
  • Override (enabled) — you switched on something this event wouldn't normally get.
  • Override (disabled) — you switched off something it would normally get.
  • Job-specific addition — added for this event only, with no rule behind it.

Good to know

  • This screen is SuperUser only. Directors can arrange their own Dashboard, but cannot add or remove widgets.
  • Attaching the first widget to an event replaces its default Dashboard layout — see the FAQ.
  • Changes are held until you Save; leaving with unsaved edits will warn you first.
