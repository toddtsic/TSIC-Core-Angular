Assign Timeslots

Step 3 of the Scheduling Checklist, and two jobs on one screen: which days an age group plays, and which field slots exist on those days for games to drop into. You work one age group at a time — pick it in the rail on the left; the badge next to each name is its pool count.

Dates first, then slots.

The days you can set up timeslots for are derived from the game dates above — not chosen separately. Add no dates and there is nothing to configure; add a Sunday date and Sunday appears in setup. The build engine reads timeslots the same way, so a row for a day you never play is never read at all.

Age Group Game Dates

The top card is the calendar for this age group. Add Date creates one; the row actions edit, delete, or clone it:

  • +D — clone to the next day. +W — clone to the same day next week. +R — clone this date carrying the next round number.
  • Rnd is the first round played on that date. Day 1 is Rnd 1; if three rounds run on Day 1, Day 2 starts at Rnd 4. Each calendar date should have its own first round — the screen warns you if two dates share one, or if every date is sitting on Round 1.

Age Group Timeslots

The bottom card is the inventory of droppable game slots. Set Up Timeslots (or Edit Timeslots once some exist) is the only way to create or change them — the table below it is a read-out, not an editor.

The setup dialog lists one row per day this age group plays. For each day you set:

Fields

Which fields host this age group that day. Tick a field to add it; untick to remove it.

Start

The first game time on the day.

Every

Minutes between game starts on a field — the interval.

Slots / field

How many games each field runs that day. Fields × slots is the day's total, shown as you type.

Saving writes the slots to every pool in the age group — you don't set them up pool by pool. The dialog totals the slots you're about to create so you can compare against the games your pairings need before you commit.

A played day with no timeslots is a silent build failure.

The builder places no games on it and says nothing. The screen calls it out above the table — "plays Sunday but has no timeslots there" — with a button straight into setup. The reverse case is flagged too: slots sitting on a day this age group has no game date for are dead rows the builder never reads.

Reading the timeslot table

Slots are stored per pool, so a 31-field age group with 6 pools is 186 near-identical rows. The table folds them: one row per field per day, with the pools it covers summarised in the last column. A row that doesn't cover every pool is highlighted and shows how many are missing.

Three counts sit above the table and mean different things:

  • Game slots — how many games actually fit. This is the number to compare against what your pairings need. Pools don't multiply it; six pools share the same physical field-hour.
  • Field/day rows — what's on screen after folding.
  • Pool timeslots — the raw stored rows. It's the number legacy displayed, and it's why the two don't match.

Copying to another age group

The Clone to control at the top copies this age group's Dates or its Fields to another age group. Set 2030 up the way you want it, then push it across.

Cloning replaces the target — it never appends.

If the target age group already has dates or timeslots, they're cleared and replaced with these. You get a confirmation naming what's about to be lost. Cloning the same thing twice is therefore safe; it can't double anything up.

Common mistakes

  • Setting up timeslots before dates. Setup is disabled until the age group has at least one game date, because the days it configures come from them.
  • Too few slots for the games needed. Compare the game-slot count against what your pools and pairings require. A shortfall means the builder runs out of room.
  • Leaving a play day empty. Heed the warning banner — a played day with no slots produces no games and no error.
  • Assuming a clone merged. It replaced. If the target had dates you wanted to keep, they're gone — re-add them rather than cloning back and forth.
